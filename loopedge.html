Loop Edge: what an overnight AI strategy search found

We asked a machine to try hundreds of trading ideas in one night and gave it one rule: an idea only counts if it survives tests its own author cannot touch. Of 356 ideas, none survived the first gate. This page shows the machine, what each test did, and how loop engineering, skill files and newer AI techniques could surface better strategies next.

Read this first. The ideas were written by AI agents; the tests are plain code that no agent can edit. A null result does not prove no edge exists. It says this search space, with this data and this bar, did not give one up. Research and paper tracking only: nothing here is advice and no money moves.

Long track

3. The gauntlet: which test killed how many ideas

An idea can fail several tests, so bars overlap. Long-track-only test: "did not replicate".

  • Weekly t-stat under 3. The average weekly profit after costs, divided by its noise. Under 3 means it could easily be luck.
  • Multiple-testing correction. Try 350 ideas and a few look good by chance. This test raises the bar as the count grows, and the count is in the log.
  • Placebo. Slide the same trades to the wrong dates 500 times. If those do about as well, the signal is not about timing.
  • Look-ahead. Cut the data off at 5 dates. If the signal changes, it was peeking at the future.
  • Halves and years. Profit must be positive in both halves of history and in 70% of calendar years.
  • Active weeks. Enough weeks with a real position that the result is more than a few lucky trades.
  • Costs. 5 basis points on every fill, both sides, baked into every number above.

5. Costs eat the signals

Each dot is an idea: average weekly profit before costs (across) and after (up), in basis points of capital. On the diagonal, costs took nothing. Below it, costs took a lot.

Reading it. Almost every dot sits at near-zero before costs. The ones far below the diagonal have signals that move a lot and pay for it. A strategy with a t of -9 is a costs finding, not a short-it-instead edge: flipping it would still pay the same costs.

8. What went wrong on our side

  • Dead signals: of the ideas barely traded. Several gas-positioning and weather ideas never fired; likely a gate or data join that never triggers (not yet diagnosed). New --smoke check now catches this before a trial is spent.
  • Look-ahead: ideas were flagged for peeking at the future by accident. The test worked; the agents wrote sloppy code.
  • Crashes: 6 ideas ended without results (4 of them involve copper). Cause not yet diagnosed.
  • Repetition: by round 4 the ideators were re-skinning storage, calendar and reversal ideas. "A thousand flowers" came out nearer forty species.
  • Survivor bias: the long track holds today's names. That flatters long-only ideas, and no idea passed anyway.
  • The big-picture work was not tested: the midterm, scenario and regime-shift thinking produced notes, not trades. The checker needs a daily rule on a price table, and "the PJM regime may flip" is not one. That part still needs a different test.
  • Money: the $60 cap stopped the run at 03:13 with the queue empty and a fourth round just launched.

9. Getting better strategies next: loops, skill files, and what is coming

Last night showed the loop works as a machine and that ideas are cheap ($0.17 each) while trustworthy tests are the scarce part. The upgrades below are things we have not built or proven. Each is listed with what it could add and what it could break.

What we used: loop engineering

A loop is a goal with a machine-checkable finish line, workers that never grade themselves, state kept on disk instead of in anyone's memory, and hard stops (time, money, trial count). Here that meant a locked checker, fenced worker sessions, a trial log, a spend cap, and doing every deterministic step in plain code so only the creative steps cost tokens. The biggest lesson: the checker is the product. A loop is only as honest as its test.

What we would add

Skill files

Reusable instruction packs (a SKILL.md file that loads only when relevant). Candidates: a hypothesis pre-registration skill, a "check this fact against a primary source" skill, a filings and transcript reading skill, and a post-mortem skill that writes what each kill taught into a shared learning file.
NOT BUILT

Red-team agent

A separate agent whose only job is to break an idea before it earns the holdout: hunt for look-ahead, survivor bias, a bad data join. It cannot edit the idea.
NOT BUILT

Planted-edge test

Inject a fake edge of known size into history and see how often the gauntlet finds it. Today we do not know the smallest real edge this checker could detect, so a null result is hard to interpret. Cheap, and it comes first.
NOT BUILT

Evolve, do not just generate

Keep a population of rules, mutate the closest calls, score each with the locked checker (the pattern behind recent evaluator-guided search systems). Every mutation is another trial, so the multiple-testing bar must rise with the count.
NOT BUILT

Primary-source retrieval

Ground ideas in filings, transcripts, tariffs and docket text instead of search summaries. Several of our own world notes came from unverified summaries; this fixes the root cause.
NOT BUILT

Forward tests as the judge

Backtests screen; calendar time decides. Dated, pre-registered forecasts scored with a Brier score are already live and are the right home for ideas a price table cannot test.

Guardrails every upgrade needs

  • More attempts need a higher bar. Every extra idea is another chance to get lucky, and the log has to count all of them.
  • Agents never edit the test, and never see the holdout.
  • Unverified facts stay labeled. A claim from a search summary is a lead, not a citation.
  • Paper first, calendar time second, a person decides about real money. Nothing on this site is advice.

10. Open forks

Run again with new data

NYISO and ISO-NE day-ahead prices (including NYISO's price for PJM) are now wired in. Another capped run costs about $60 and the odds are low; it is mainly the first run on data that has not been picked over.

Lower the bar

Not an option we are taking. At t of 3, luck alone gives about one hit per 350 tries, so loosening it mostly lets noise through. We widen the data instead.

Pre-registered event forecasts

For shifts a backtest cannot see: write the prediction, the dated signpost and what would prove it wrong now, then score it. A first batch on the December auction, the January load forecast, state affordability moves and hyperscaler spending is going into the forecast log (shown on the Energy calendar page).

Change what the search is for

This machine hunts daily stock signals. A slower, larger thesis (a regime, an auction outcome, a re-rating) needs a different test, which is what the forecast log is for.
